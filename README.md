# OKX Monitor & Light Trader

Бот для круглосуточного мониторинга рынка и лёгкой спотовой торговли на OKX.
Python 3.11, ccxt + websockets, SQLite, локальный веб-интерфейс (aiohttp, без внешних сервисов).
Работает локально на Windows 11 (venv, без Docker), код кроссплатформенный (пути через `pathlib`).
Управление и вся аналитика — в браузере на этом же компьютере: http://127.0.0.1:8765.

> ⚠️ Торговля по умолчанию **выключена** и работает в **DEMO**-режиме OKX
> (заголовок `x-simulated-trading: 1`). Только спот, только лонги, без плеча и фьючерсов.
> Никакая стратегия не гарантирует прибыль: сначала прогоните бэктест и поработайте на демо.

## Возможности

| Модуль | Что делает |
|---|---|
| **collector** | WebSocket OKX: свечи 1m/5m/1h (`/ws/v5/business`) и тикеры (`/ws/v5/public`) по списку монет. Автореконнект с экспоненциальной паузой, ping/pong, backfill пропусков через REST после каждого (пере)подключения, хранение в SQLite, очистка старых 1m/5m. |
| **alerts** | Движение > X% за N минут · пробой и отскок от 24h/7d high/low · RSI(14) 1h > 75 / < 25 · всплеск объёма > 3x среднего · пересечение EMA 50/200 на 4h. Cooldown на каждое правило и монету (переживает рестарт), кнопка «Скрыть алерты». |
| **analytics** | Утренний дайджест 09:00 (Europe/Moscow): изменение 24h, волатильность, уровни (24h/7d, pivot/R1/S1), RSI, тренд 4h, корреляция с BTC. Недельный отчёт в воскресенье. Опционально — краткий разбор от Claude (модель из конфига, ключ в `.env`, дневной лимит $). |
| **trader** | Выключен по умолчанию. Тренд EMA50 > EMA200 на 4h + вход на 1h (по умолчанию — пробой 20-часового максимума при аптренде BTC; прежний откат RSI — `entry_mode: pullback`), SL/TP по ATR с ограничением стопа `stop_loss_pct`, только лонги. ≤ 1 позиции на монету, ≤ 2 одновременно, размер ≤ 30% бюджета сессии, SL 2% / TP 4% (настраиваются). SL/TP контролирует бот на каждом тике **и** OCO-ордер на бирже (защищает, пока ПК спит). Каждая сделка и причина входа — в БД и в ленте событий интерфейса. Опционально — 5-минутный скальпинг (`entry_mode: scalp_revert / scalp_breakout`, см. [ниже](#частые-сделки-скальпинг-5m)). Комиссии учитываются в PnL. |
| **protections** | Защиты входа по образцу Freqtrade: CooldownPeriod, StoplossGuard, LowProfitPairs, MaxDrawdown. Считаются из истории закрытых сделок (переживают рестарт), только блокируют входы. По умолчанию выключены. |
| **exits** | Барьеры выхода по образцу Hummingbot (triple barrier): трейлинг-стоп, перевод в безубыток, лимит времени удержания. Стоп только поднимается, OCO на бирже переставляется вслед. По умолчанию выключены. |
| **pairlist** | Динамический отбор 3–5 пар OKX spot /USDT: объём, спред, глубина стакана, ATR%, возраст листинга, стейблкоины, плечевые токены, признаки манипуляций, whitelist/blacklist, пересчёт раз в N часов. По умолчанию выключен. |
| **web UI** | Локальный интерфейс: обзор сессии, сделки, аналитика (накопленный PnL, по дням/парам/часам, причины выходов), график свечей со входами/выходами, история сессий, лента событий, результаты бэктестов, настройки. Кнопки: старт/завершение сессии, изменение параметров (в пределах `hard_caps`), пауза, trader вкл/выкл, аварийный «Стоп». |
| **risk/session** | Торговые «сессии» с бюджетом, таймером, лимитом убытка, целью/profit-lock, лимитами сделок/серии убытков, дневными лимитами и неизменяемыми из интерфейса `hard_caps`. Чистая логика без I/O — та же используется в бэктесте и покрыта тестами. |

## Установка

Нужен Python **3.11** (64-bit) с python.org, при установке отметьте «Add python.exe to PATH».

```bat
git clone <repo> C:\bots\tradingbot
cd C:\bots\tradingbot
setup.bat
```

`setup.bat` создаёт `.venv`, ставит зависимости и копирует `config.example.yaml → config.yaml`,
`.env.example → .env`. Вручную то же самое:

```bat
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
copy config.example.yaml config.yaml
copy .env.example .env
```

За корпоративным прокси бот берёт `HTTPS_PROXY` и CA-бандл (`SSL_CERT_FILE` /
`REQUESTS_CA_BUNDLE`) из переменных окружения.

Перед первым запуском — предстартовая проверка (ничего не покупает): конфиг, ключи (значения не
выводятся), режим DEMO, связь с OKX по REST и WebSocket, баланс демо-счёта, права ключа (без
Withdraw), свободен ли порт интерфейса:

```bat
.venv\Scripts\python scripts\preflight.py
```

Запуск: `start.bat` (бот в фоне + браузер с интерфейсом) или в консоли (Ctrl+C — штатная остановка):

```bat
.venv\Scripts\python main.py
```

и откройте http://127.0.0.1:8765.

## Ключи OKX

**Демо (начинайте с него):**
1. okx.com → войти → переключатель **Demo trading** (вверху справа / в меню Trade).
2. В демо-режиме: профиль → **API** → **Create Demo Trading V5 API Key**.
3. Права: **Read + Trade**. **Withdraw НЕ включать.**
4. Задайте passphrase, сохраните key / secret / passphrase в `.env`:
   `OKX_DEMO_API_KEY`, `OKX_DEMO_API_SECRET`, `OKX_DEMO_API_PASSPHRASE`.
5. Демо-счёт пополняется виртуальными средствами в интерфейсе демо-торговли.

**Реальный счёт:** профиль → API → Create API key, права **Read + Trade, без Withdraw**.
Привязку к IP включайте **только если у вас статический IP** (иначе бот перестанет работать
при смене адреса). Ключи — в `OKX_API_KEY/SECRET/PASSPHRASE`, см. [чеклист](#чеклист-перехода-с-демо-на-реал).

Счёт OKX должен быть в режиме, где доступна спот-торговля (Spot / Spot & futures / Multi-currency —
любой). Ключи хранятся **только** в `.env`; логгер маскирует их значения, `.env` в `.gitignore`.

## Интерфейс

Бот поднимает страницу **только на 127.0.0.1** (порт `ui.port`, по умолчанию 8765) — с других
компьютеров и из интернета она недоступна; `ui.host` с другим адресом игнорируется. `start.bat`
открывает её сам. При каждом запуске бота создаётся новый токен доступа: если бот перезапустился,
просто обновите страницу. Защита от сторонних сайтов: проверка заголовка Host, токен в каждом
запросе, только JSON в POST, запрет встраивания во фреймы.

| Вкладка | Что там |
|---|---|
| **Обзор** | PnL сессии (реализ./нереализ./комиссии), позиции с SL/TP, полосы «использовано лимита убытка / путь к цели / время», кнопки сессии и изменения параметров, последние события, накопленный PnL всех сделок |
| **Сделки** | все сделки с фильтром по паре и статусу: вход/выход, PnL с комиссиями, причина входа, тип выхода |
| **Аналитика** | за 24ч/7д/30д/всё: сделки, винрейт, PnL до и после комиссий, profit factor, ожидание на сделку, макс. просадка, среднее удержание; графики накопленного PnL, по дням, по парам, по часу входа, причины выходов |
| **Рынок** | свечи 1m/5m/1h из базы бота с отметками входов и выходов, таблица цен и изменения за 24ч |
| **Сессии** | история сессий с причиной остановки и отчётом |
| **События** | лента: сделки, сессии, алерты рынка, отчёты, предупреждения, ошибки |
| **Бэктест** | результаты `scripts/research.py` и `scripts/research_scalp.py` |
| **Настройки** | стратегия, лимиты, `hard_caps`, расписание, защиты, отбор пар (только чтение — меняются в `config.yaml`) |

## Конфигурация

Полный пример с комментариями — [config.example.yaml](config.example.yaml). Любой отсутствующий
ключ берётся из значений по умолчанию (`bot/config.py`). Ключевые блоки:

```yaml
symbols: [BTC/USDT, ETH/USDT, SOL/USDT, XRP/USDT, DOGE/USDT, ADA/USDT, LTC/USDT, LINK/USDT,
          AVAX/USDT, BCH/USDT, DOT/USDT, TRX/USDT, BNB/USDT, ETC/USDT, XLM/USDT, ZEC/USDT]   # 16 пар из исследования

alerts:
  price_move: [{pct: 2.0, minutes: 15}, {pct: 4.0, minutes: 60}]
  rsi: {enabled: true, period: 14, overbought: 75, oversold: 25}
  volume_spike: {enabled: true, timeframe: 5m, multiplier: 3.0, lookback: 20}
  cooldown_minutes: {default: 60, price_move: 30, levels: 120, rsi: 240, volume_spike: 60, ema_cross: 720}

trader:
  enabled: false
  exchange_side_sl_tp: true
  strategy: {ema_fast: 50, ema_slow: 200, rsi_period: 14, rsi_pullback: 35, rsi_max_entry: 60}

session_defaults:            # используются, если не заданы при старте сессии
  budget_usdt: 10
  duration_hours: 8
  max_loss_usdt: 2
  profit_target_usdt: 1.5
  profit_lock: false
  profit_lock_trail_pct: 30
  max_trades: 10
  max_consecutive_losses: 3
  consecutive_loss_action: pause   # pause | stop
  on_session_end: close_all        # close_all | manage_only
  manage_only_max_minutes: 60
  no_entry_last_hours: 4           # не открывать входы за 4ч до конца сессии (≤ половины сессии)
  stop_loss_pct: 2
  take_profit_pct: 4

hard_caps:                   # интерфейс НЕ может их превысить
  max_budget_usdt: 50
  max_loss_usdt: 10
  max_duration_hours: 24

daily_caps:
  daily_budget_cap_usdt: 30
  daily_loss_cap_usdt: 5

schedule:                    # сессия каждый день в 00:00 на 8 часов
  enabled: true
  start_time: "00:00"
  days: [mon, tue, wed, thu, fri, sat, sun]
  params: {budget_usdt: 10, duration_hours: 8, max_loss_usdt: 2}
```

**Пример «осторожный»:** `budget_usdt: 10, max_loss_usdt: 1, profit_target_usdt: 1, max_trades: 4,
max_consecutive_losses: 2, consecutive_loss_action: stop`.
**Пример «дать прибыли бежать»:** `profit_target_usdt: 1, profit_lock: true, profit_lock_trail_pct: 30,
on_session_end: manage_only, manage_only_max_minutes: 120`.

Claude-разбор дайджеста: `analytics.llm.enabled: true`, ключ `ANTHROPIC_API_KEY` в `.env`.
Модель (`model`), цены за 1M токенов (`price_input_per_mtok`/`price_output_per_mtok`) и
дневной лимит (`daily_budget_usd`) — в конфиге. Перед запросом бот оценивает худший случай
стоимости и пропускает вызов, если лимит дня будет превышен; фактическая стоимость считается по
`usage` ответа. По умолчанию включён серверный fallback при отказе модели (`refusal_fallback`).

## Сессии и лимиты

Торговля идёт только внутри активной сессии.

* **Старт** — кнопка «Запустить сессию» в интерфейсе или по расписанию. Перед стартом проверяется: параметры в пределах
  `hard_caps`; **реальный свободный USDT на бирже ≥ бюджета**; `daily_budget_cap_usdt` (сумма бюджетов
  всех сессий за день); дневной лимит убытка ещё не достигнут; trader включён; нет файла `STOP`;
  реальный счёт подтверждён. Иначе сессия не стартует, причина показывается в интерфейсе.
* **Бюджет** — бот никогда не использует больше `budget_usdt`, даже если на счёте больше.
  Прибыль не реинвестируется сверх бюджета, убытки уменьшают доступный капитал.
  Позиция ≤ `position_size_pct` (≤ 30%) бюджета, ≤ 2 позиции, ≤ 1 на монету.
* **PnL сессии** = реализованный + нереализованный, **с учётом комиссий**: комиссия входа (OKX
  берёт её в базовой валюте при покупке — учитывается через фактически полученное количество) и
  оценка комиссии выхода в нереализованном PnL. Лимиты проверяются **на каждом тике** (событие
  тикера или раз в `tick_interval_sec`), а не только после закрытия сделки.
* **Остановки:**

| Условие | Действие |
|---|---|
| `max_loss_usdt` / `max_loss_pct` (берётся меньший, и никогда не больше `hard_caps.max_loss_usdt`) | закрыть всё по рынку, завершить |
| `daily_loss_cap_usdt` (все сессии за день + текущая) | закрыть всё, завершить |
| `profit_target_usdt` / `_pct`, `profit_lock: false` | закрыть всё, зафиксировать прибыль |
| цель + `profit_lock: true` | продолжить, включить трейлинг: стоп, если PnL упал на `profit_lock_trail_pct`% от пика |
| истекло `duration_hours` | по `on_session_end`: `close_all` — закрыть всё; `manage_only` — новые не открывать, текущие до SL/TP, но не дольше `manage_only_max_minutes`, затем закрыть |
| `max_trades` | новые не открывать; когда позиции закрылись — завершить |
| `max_consecutive_losses` | `pause` — пауза `consecutive_loss_pause_minutes`; `stop` — завершить по `on_session_end` |
| кнопка «Завершить сессию» | по `on_session_end` |
| кнопка **«Стоп»** или файл `STOP` | закрыть всё немедленно, trader выключить |

* **Отчёт** в конце каждой сессии: причина остановки (время / лимит убытка / цель / трейлинг /
  ручная / аварийная …), сделки, PnL с комиссиями, комиссии, винрейт, макс. просадка, пик PnL.
* **hard_caps** — максимальный бюджет, убыток, длительность (+ число сделок, размер позиции,
  число позиций). Интерфейс (старт сессии и «Изменить параметр») отклоняет значения выше. Поднять потолки можно
  только правкой `config.yaml` и перезапуском.

## Управление

Всё — кнопками в интерфейсе (бывшие команды Telegram):

| Действие | Где |
|---|---|
| Запустить сессию (бюджет, длительность, макс. убыток, цель, сделки, по окончании) | «Обзор» → форма с кнопкой «Запустить сессию» (видна, когда сессии нет); пустые поля — из `session_defaults` |
| Изменить параметр на лету (в пределах `hard_caps`) | «Обзор» → «Изменить параметр» |
| Завершить сессию | «Обзор» → «Завершить сессию» (по `on_session_end`) |
| Пауза/возобновление новых входов | «Обзор» → «Пауза входов» |
| **Аварийно** закрыть всё и выключить trader | красная кнопка **«Стоп»** в шапке (с подтверждением) |
| Включить/выключить trader | кнопка в шапке |
| Подтвердить реальный счёт | поле кода появляется в «Обзоре», только при `OKX_LIVE_TRADING=true` |
| Дайджест сейчас, скрыть алерты на 1 ч | «События» |
| Пересчитать торгуемые пары (если `pairlist.enabled`) | «Настройки» → «Торгуемые пары» |

Файл **`STOP`** в папке проекта = кнопка «Стоп» (работает, даже если интерфейс не открывается). Пока
файл существует, trader не включится. Файл `SHUTDOWN` (его создаёт `stop.bat`) — штатная остановка
процесса **без** закрытия позиций.

## Надёжность

* **Heartbeat**: каждый компонент (WS, тики, trader) отмечается; если какой-то молчит > 5 мин —
  предупреждение в ленте событий и в шапке интерфейса. Плюс внешний `scripts/watchdog.py` (Task
  Scheduler, каждые 5 мин) читает `data/heartbeat.json` и показывает уведомление Windows (и пишет в
  `logs/watchdog.log`), **даже если процесс бота умер**.
* **Перезапуск / сон**: состояние сессии (время старта, бюджет, PnL, пик, позиции, счётчики)
  сохраняется в SQLite на каждое изменение и каждые 15 с. После рестарта или пробуждения бот:
  восстанавливает активную сессию (таймер считается от исходного старта), ищет «подвисшие»
  ордера по `clOrdId`, сверяет каждую позицию с реальным балансом (если OCO сработал, пока бот
  не работал — сделка закрывается по фактическим fill'ам), сверяет USDT. **Новая сессия
  автоматически не стартует** (слот расписания, пропущенный во время сна/простоя, не догоняется).
  Сон определяется по «скачку» времени в event loop, после чего WS переподключается и делается backfill.
* **Устаревшие данные**: нет тиков > 60 с → новые входы на паузе + уведомление; для лимитов и SL
  цены позиций берутся через REST.
* **Ошибки API**: ретраи с экспоненциальной паузой на сетевые ошибки и rate limit (ccxt
  `enableRateLimit`), ордера не повторяются вслепую — сначала поиск по `clOrdId`.
* **Логи**: `logs/bot.log` и `logs/errors.log` с ротацией (10 МБ × 10), секреты маскируются.
* **Один экземпляр**: `data/bot.lock` не даёт запустить два бота одновременно.

## Защиты, барьеры выхода и отбор пар

По умолчанию включено только то, что прошло проверку `scripts/evaluate_improvements.py` на 2 годах
реальной истории OKX: **лимит удержания позиции 6ч** (`trader.exits.time_limit_hours: 6`) и **запрет
новых входов за 4ч до конца сессии** (`session_defaults.no_entry_last_hours: 4`).
Защиты, трейлинг, безубыток и динамический отбор пар реализованы, но выключены. Результаты и
честная оценка — в [IMPROVEMENTS.md](IMPROVEMENTS.md): даже после улучшений стратегия в бэктесте
убыточна, переход на реальный счёт не рекомендуется.
Ни один из них не ослабляет лимиты сессии, `hard_caps`, кнопку «Стоп» и файл `STOP`.

* `trader.protections` — блокировки входов, считаются из закрытых сделок **всех** сессий:
  `cooldown_minutes` (пауза по паре после выхода), `stoploss_guard` (N стоп-лоссов за окно → пауза по
  всем парам), `low_profit_pairs` (пара в минусе за окно → пауза по паре), `max_drawdown` (просадка
  реализованного PnL за окно → пауза по всем). Активные блокировки видны на вкладке «Обзор».
* `trader.exits` — `trailing_*`, `breakeven_*`, `time_limit_hours`. Стоп поднимается и на бирже (OCO
  перевыставляется не чаще раза в 30 с и только при сдвиге ≥ 0.3%).
* `pairlist` — при `enabled: true` бот торгует 3–5 пар, отобранных из всех OKX spot */USDT:
  1. дешёвые фильтры по тикерам: объём 24ч ≥ `min_quote_volume_usdt`, цена, стейблкоины, плечевые токены, blacklist;
  2. `candidates` самых ликвидных — детально: спред ≤ `max_spread_pct`, глубина стакана в ±`depth_band_pct`%
     ≥ `min_depth_usdt` с каждой стороны, ATR%(14, 1d) в [`min_atr_pct`; `max_atr_pct`], возраст
     листинга ≥ `min_listing_days` (по `listTime` OKX), признаки манипуляций (изменение за 24ч,
     всплеск объёма к медиане 30 дней, экстремальные дневные диапазоны), минимальный ордер биржи
     не больше половины размера позиции;
  3. сначала `whitelist` (если прошли фильтры), затем по убыванию объёма, максимум `max_pairs`.

  Список пересчитывается раз в `refresh_hours`, хранится в БД (переживает рестарт); при изменении —
  событие в ленте и переподписка WebSocket. Позиции по парам, выпавшим из списка, ведутся до
  выхода. Мониторинг/алерты/дайджест продолжают работать по `symbols`. Проверить, что выбрал бы бот
  сейчас: `python scripts/select_pairs.py`.

## Частые сделки (скальпинг 5m)

`trader.strategy.entry_mode: scalp_revert | scalp_breakout` — входы на закрытии каждой 5-минутной свечи
внутри аптренда 1h. S1 — возврат к среднему (Боллинджер + RSI), S2 — пробой с объёмом. SL/TP — по ATR 5m,
стоп не шире `stop_loss_pct` сессии. Все лимиты сессии, `hard_caps` и кнопка «Стоп» действуют так же.

**Результат бэктеста** (`scripts/research_scalp.py`, год 5m-истории, 16 пар, издержки 0.15% на сторону):
оба варианта убыточны. На последних 4 месяцах: S1 — −9.5 USDT за 1175 сделок, S2 — −26.0 USDT за
2994 сделки. Без комиссий — около нуля (+0.8 / +1.2). Подробности — [IMPROVEMENTS.md](IMPROVEMENTS.md),
раздел 8. Поэтому по умолчанию режим **выключен** и разрешён только на DEMO.

**Посмотреть на демо:** интерфейс → «Настройки» → «Режим стратегии» → «Скальпинг 5m: …» → «Применить»
(когда нет открытых позиций), затем запустить сессию на «Обзоре». Выбор сохраняется в базе и
переживает перезапуск; `config.yaml` не меняется. В этом режиме пустые поля сессии берутся такими:
24 ч, до 50 сделок, без входов в последний час (в пределах `hard_caps`); позиция закрывается не позже
чем через 1 ч. На реальном счёте переключатель недоступен, сохранённый выбор игнорируется, а trader
откажется торговать скальп-режимом, даже если его вписать в `config.yaml`.

## Бэктест

```bat
.venv\Scripts\python backtest.py --days 365 --per-pair --walk-forward 4 --monte-carlo 5000 --lookahead-check
.venv\Scripts\python scripts\evaluate_improvements.py --days 365
.venv\Scripts\python backtest.py --days 180 --compare
.venv\Scripts\python backtest.py --days 365 --compare budget=10 hours=8 max_loss=1 target=1 lock=on trail=30
.venv\Scripts\python backtest.py --symbols BTC/USDT ETH/USDT --start-hour 9 end=manage_only --trades-csv data\trades.csv
```

История 1h качается с OKX (публичный API, без ключей) и кэшируется в `data/backtest/`.
Используются **тот же** `RiskEngine` и та же стратегия, что и в живой торговле: сессии стартуют
каждый день в `--start-hour` (по умолчанию из `schedule.start_time`), действуют дневные лимиты.
SL/TP — внутри бара по high/low (если задеты оба — пессимистично считается SL), трейлинг поднимает
стоп только со следующего бара, лимиты убытка проверяются по минимумам бара, затем по закрытию;
комиссия — `exchange.taker_fee` (меньше 0.1% на сторону бэктест не принимает), проскальзывание
`--slippage` на каждой сделке. Защиты и барьеры выхода — те же модули, что в живой торговле.

* `--per-pair` — результат по парам с t-статистикой (|t| < 2 — неотличимо от нуля).
* `--walk-forward K` — K последовательных независимых окон: стабилен ли результат во времени.
* `--monte-carlo N` — бутстреп последовательности сделок: разброс PnL (p5…p95), P(PnL>0), просадка p95.
* `--lookahead-check` — как lookahead-analysis во Freqtrade: сигналы и индикаторы, посчитанные на всей
  истории, сравниваются с посчитанными на истории, обрезанной на этом баре.
* `--offline` — только кэш `data/backtest/` (воспроизводимый прогон без сети).
* `scripts/evaluate_improvements.py` — каждое улучшение против базы: не хуже in-sample, лучше
  out-of-sample, лучше в ≥ половине окон walk-forward и без роста просадки > 25%; итог — в
  `data/backtest/evaluation.md`. `--compare` дополнительно прогоняет стратегию без лимитов сессии (только SL/TP, 24/7) —
так видно, как лимиты влияют на результат (PnL, просадку, число сделок, причины остановок).

## Чеклист перехода с демо на реал

1. ☐ Бэктест на 6–12 мес. с вашими лимитами (`--compare`) — результат понятен и приемлем.
2. ☐ Минимум 2–4 недели на DEMO: сессии стартуют/заканчиваются как ожидается, отчёты корректны,
   кнопка «Стоп» и файл `STOP` проверены, рестарт и сон ПК проверены (сессия восстанавливается).
3. ☐ Реальный API-ключ: **Read + Trade, без Withdraw**; IP-привязка только при статическом IP.
4. ☐ На счёте лишь та сумма, которую вы готовы потерять; `hard_caps` и `daily_caps` выставлены
   **маленькими** (например, `max_budget_usdt: 20`, `max_loss_usdt: 3`, `daily_loss_cap_usdt: 3`).
5. ☐ `session_defaults` проверены, `schedule.enabled` — осознанно.
6. ☐ В `.env`: `OKX_API_KEY/SECRET/PASSPHRASE` и `OKX_LIVE_TRADING=true`. Перезапуск.
7. ☐ Бот покажет код в окне терминала/логе и попросит ввести его в интерфейсе (подтверждение привязано к
   отпечатку ключа; смена ключа требует нового подтверждения). Без него торговля заблокирована.
8. ☐ «Включить trader», затем первая сессия с минимальным бюджетом; убедитесь, что OCO-ордера появились
   в интерфейсе OKX («Алгоритмические ордера»).
9. ☐ Сон ПК отключён, Task Scheduler/NSSM и watchdog работают, алерт «бот молчит» проверен
   (остановите бота на 6+ минут).
10. ☐ Откат на демо: `OKX_LIVE_TRADING=false` + перезапуск.
